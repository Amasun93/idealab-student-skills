# ideaLab 演讲答辩

把本模块作为 `idealab-student-skills` 的内置能力使用。学生不需要记住模块名称；识别到答辩、成果展示、演讲稿或答辩练习意图后，直接进入本流程。

## 工作原则

始终维护这条因果链：

```text
目标人群的问题
→ 现有方案怎样解决
→ 仍有什么不足
→ 本项目用哪些功能回应不足
→ 这些功能形成什么亮点或创新
→ 用什么实验验证核心目标
```

页面数量和版式可以变化，因果链不能断。每个功能必须能够回指一个真实问题或核心指标；每个实验必须能够回指一个目标、功能或性能指标。

遵守以下边界：

- 先理解项目和本地材料，再决定页面；不要先套固定页数。
- 先盘点、再确认、后生成。未得到确认前不要生成最终演示。
- 真实素材优先。AI示意图不能冒充原型、制作过程或实验证据。
- 不把学生没确认的个人经历、贡献和实验数据写成事实。
- 帮学生走完整条答辩逻辑，不把表达变成学术论文审查。
- 一次只问一个短问题；优先让学生说，再整理答案。

## 按需读取参考

- 开始梳理项目逻辑前，读取 [project-design-methodology.md](references/project-design-methodology.md)。
- 设计章节、页面内容和图文结构时，读取 [presentation-framework.md](references/presentation-framework.md)。
- 扫描材料、决定可用/缺失/可生成内容时，读取 [materials-and-evidence.md](references/materials-and-evidence.md)。

## 执行流程

### 1. 识别学生与目标

优先读取当前目录及父目录中的 `学生项目档案.json`，确认学生姓名、年级、项目全名、项目简称和档案根目录。缺少项目简称时，根据项目名称提出一个简短候选并让学生确认。

只补问会改变生成结果的信息：

1. 当前是开题展示、阶段展示还是成果答辩。
2. 学生年级；无法确定时按初中层级设计，并标记“年级待确认”。
3. 默认生成 HTML；只问一次是否还需要 PPTX。

输出文件始终以“姓名-项目简称”开头。

### 2. 盘点全部本地材料

扫描学生档案中的开题书、手册、图纸、代码、关键图片、视频、日志、已有PPT和实验记录。查看文件内容、图片画面和视频关键帧，不只按文件名判断。

按 [materials-and-evidence.md](references/materials-and-evidence.md) 生成素材盘点，至少分为：

- 完整可用：文件、用途、拟放章节。
- 可用但需确认：不确定的人物、场景、日期、实验含义或版本。
- 缺失待补：需要什么、建议谁补、将出现在哪一页。
- 允许AI生成：封面背景、问题场景示意、现有方案示意或解释图。
- 不使用：重复、低清、无关、无法辨认或存在隐私风险的材料。

先向用户展示“将使用什么、将生成什么、仍缺什么、准备怎样安排页面”，等待确认。需要生图时同时提醒：“后续需要生成视觉素材，请切换到生图能力较好的模型再继续。”

### 3. 重建项目因果链

从材料中提取目标人群、生活问题、问题普遍性、现有方案、核心不足、唯一核心目标、功能、技术实现、原型状态和实验状态。

遇到冲突或逻辑断点时，只追问当前最关键的一项。不得用新增功能掩盖目标不清。使用下面三项检查：

- **功能检查**：删除该功能后，核心目标是否更难实现？若否，降为辅助功能或删除。
- **创新检查**：每个亮点必须说明“相比什么，具体改善了什么”。
- **实验检查**：实验指标必须能说明核心问题是否得到改善，或装置性能是否满足使用需要。

### 4. 确定动态页面

依据 [presentation-framework.md](references/presentation-framework.md) 选择章节和页面。保持“背景与现状—目标与方案—制作与原型—实验与分析—总结”的章节顺序，但允许：

- 没有有意义的访谈/问卷时省略调研页。
- 图纸或原理复杂时拆页。
- 制作、实验素材较多时按关键选择或实验主题增页。
- 没有真实制作、原型或实验素材时保留必要的“丢失/待补”占位，不伪造证据。

每页只承担一个主要结论。页面标题优先写结论，不只写“项目背景”“实验结果”等栏目名。

### 5. 生成内容与演示

默认生成本地素材可离线打开的 HTML；用户选择后再同步生成 PPTX。优先使用模块内确定性脚本和模板，不临时自由编写另一套生成器。

按 [defense-spec.schema.json](references/defense-spec.schema.json) 形成答辩内容 JSON，并依次运行：

```bash
node modules/idealab-presentation/scripts/scan-defense-materials.mjs --archive "学生档案" --output "06 答辩ppt" --name "姓名-项目简称"
node modules/idealab-presentation/scripts/validate-defense-spec.mjs --input "答辩内容.json"
node modules/idealab-presentation/scripts/build-idealab-presentation.mjs --input "答辩内容.json" --inventory "姓名-项目简称-答辩素材盘点.json" --output "06 答辩ppt"
```

扫描结果只能提供候选，AI必须查看文档、图片画面和视频关键帧后再请用户确认。确认后先把每个检查项的 `needs-review` 改为 `present`、`missing` 或 `not-applicable`；实际使用的文件还要把 `review_status` 改为 `approved` 并核对 `origin`。新生成的示意图加入盘点 `items`，标记 `origin: ai` 与 `review_status: approved`。最后再把盘点 JSON 的 `review.confirmed` 与答辩内容的 `plan_confirmed` 设为 `true`。生成器会核对两份文件来自同一个学生档案，并逐项确认所有引用图片；不会联网，也不会自行制造证据素材。

内容要求：

- 封面使用契合项目主题的全幅背景图，标题和学生信息用HTML/PPT文字叠加；背景图内不要生成中文文字，不放 ideaLab logo。
- 正文使用简洁的“标题 + 精炼文字 + 图片/图表”结构，保证投屏可读。
- 现有方案必须围绕项目痛点比较；不足要自然引出本项目优势和创新。
- 本地原型、过程和实验素材缺失时显示明确占位，写清要补的画面，不用AI假图替代。
- 生成的插图标注“AI生成示意图”或“概念示意”，避免与真实证据混淆。
- 已选择的素材必须全部实际显示；不能因版式容量不足而静默丢弃。

### 6. 整理实验

按 [experiments.md](references/experiments.md) 逐项采访学生已有实验；根据年级决定功能验证、效率对比和性能测试的深度。

有记录时，从确认的数据生成表格、图表和结论。没有记录时，生成可执行的实验计划和记录表；若学生能确认做过什么及观察结果，可整理为定性结论，但不得发明次数、成功率或精确数值。

### 7. 生成逐页参考稿与练习页

按 [speaker-script-and-defense.md](references/speaker-script-and-defense.md) 为每页生成自然、口语化的参考讲法和过渡句。讲稿服务于学生理解，不逐字朗读页面文字；个人经历、贡献和数据缺口保留醒目占位。

另生成独立交互练习页，按项目材料给出背景与目标、方法与实验、整体理解与个人贡献等问题。参考答案默认折叠，允许换题、标记“已经会了/还需练习”并显示进度。不要自动强迫学生进入实时模拟答辩。

### 8. 验收与保存

至少输出：

```text
{姓名}-{项目简称}-答辩素材盘点.md
{姓名}-{项目简称}-答辩演示.html
{姓名}-{项目简称}-答辩逐页参考稿.md
{姓名}-{项目简称}-答辩练习.html
{姓名}-{项目简称}-答辩PPTX.pptx   # 仅在用户选择时
```

保存到当前学生档案的 `06 答辩ppt` 下，保留本地素材副本和相对路径；同名时使用 `-v2`、`-v3`，不得覆盖旧版。

完成前逐项确认：

- 姓名和项目简称正确，且出现在演示封面和文件名中。
- 因果链完整，现有方案不足确实引出本项目亮点。
- 页面没有文字溢出、图片变形、重叠、断图或选中素材丢失。
- 所有真实/生成/缺失内容均正确标记。
- 实验结论与学生确认的材料一致，深度符合年龄段。
- 逐页参考稿与演示页一一对应，练习页折叠和进度交互可用。
- HTML可离线打开并适合16:9投屏；PPTX如生成则页数一致且可打开。
