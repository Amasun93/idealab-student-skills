# ideaLab 演讲答辩

把本模块作为 `idealab-student-skills` 的内置能力使用。学生不需要记住模块名称；识别到答辩、成果展示、演讲稿或答辩练习意图后，直接进入本流程。

## 工作原则

始终维护这条因果链：

```text
目标人群的问题
→ 现有方案怎样解决
→ 仍有什么不足
→ 本项目用哪些功能回应不足
→ 这些功能形成什么亮点或创新
→ 用什么实验验证核心目标
```

页面数量和版式可以变化，因果链不能断。每个功能必须能够回指一个真实问题或核心指标；每个实验必须能够回指一个目标、功能或性能指标。

遵守以下边界：

- 先理解项目和本地材料，再决定页面；不要先套固定页数。
- 先盘点、再确认、后生成。未得到确认前不要生成最终演示。
- 真实素材优先。AI示意图不能冒充原型、制作过程或实验证据。
- 不把学生没确认的个人经历、贡献和实验数据写成事实。
- 帮学生走完整条答辩逻辑，不把表达变成学术论文审查。
- 一次只问一个短问题；优先让学生说，再整理答案。

## 学生直接使用模式

默认先判断当前对话对象：学生本人使用时进入“学生模式”；老师提出批量盘点、统一确认或版本管理时进入“老师模式”。

学生模式必须降噪：

- 只向学生展示“已经找到”“还需要补充”“下一步做什么”三部分，不展示JSON字段、schema、命令、构建日志或英文状态值。
- 每轮只问一个学生能直接回答的问题。需要连续确认多个事实时，等学生回答后再问下一项。
- 不讨论模型品牌和选择。优先静默使用当前可用的图片能力；确实无法生成时，只告诉老师一次，不把技术选择交给学生。
- 补拍要求使用生活化描述，例如“拍一张鱼灯正面全景，灯要亮起来”，不要只说“补充原型证据”。
- 生成完成后先打开最终HTML，让学生看到成品，再告诉他缺图位置和练习入口。

老师模式可以使用详细表格并一次确认多项，但最终给学生看到的演示和提示仍使用学生语言。

## 执行流程

### 1. 识别学生与目标

优先读取当前目录及父目录中的 `学生项目档案.json`，确认学生姓名、年级、项目全名、项目简称和档案根目录。缺少项目简称时，根据项目名称提出一个简短候选并让学生确认。

只补问会改变生成结果的信息：

1. 当前是开题展示、阶段展示还是成果答辩。
2. 学生年级；无法确定时按初中层级设计，并标记“年级待确认”。
3. 默认生成 HTML；只有老师明确提出时再生成 PPTX，不把格式选择题交给学生。

输出文件始终以“姓名-项目简称”开头。

### 2. 盘点全部本地材料

扫描学生档案中的开题书、手册、图纸、代码、关键图片、视频、日志、已有PPT和实验记录。每次以实际文件系统递归扫描结果为准；`交付清单.json`、项目卡或旧盘点只作线索，数量冲突时不能覆盖实际文件。查看文件内容、图片画面并预览视频内容，不只按文件名判断。

遇到 `.mp` 文件时按 Mind+ 项目包处理：先检查ZIP结构并读取页面、图形化程序和文本代码摘要，不能把它当成一个无法读取的普通文件。一个目录存在多套 `.mp` 或代码时逐个检查，避免只读取第一套程序。

视频要单独区分“学生演示版”和“老师/教师参考版”。最终答辩只选择学生本人操作、讲解或展示作品的视频；老师版仅用于帮助理解项目，不能嵌入学生答辩。无法判断人物身份时先询问老师或学生，不得猜测。没有学生演示版时建立“待补拍学生演示视频”占位，不得用老师版替代。

按 [materials-and-evidence.md](references/materials-and-evidence.md) 生成素材盘点，至少分为：

- 完整可用：文件、用途、拟放章节。
- 可用但需确认：不确定的人物、场景、日期、实验含义或版本。
- 缺失待补：需要什么、建议谁补、将出现在哪一页。
- 允许AI生成：封面背景、问题场景示意、现有方案示意或解释图。
- 不使用：重复、低清、无关、无法辨认或存在隐私风险的材料。

先向用户展示“将使用什么、将生成什么、仍缺什么、准备怎样安排页面”，等待确认。学生模式使用三段口语清单；老师模式可以使用详细表格。需要生图时直接使用当前图片能力，不向学生讨论模型名称；只有能力不可用时再向老师说明。

### 3. 重建项目因果链

从材料中提取目标人群、生活问题、问题普遍性、现有方案、核心不足、唯一核心目标、功能、技术实现、原型状态和实验状态。

遇到冲突或逻辑断点时，只追问当前最关键的一项。不得用新增功能掩盖目标不清。使用下面三项检查：

- **功能检查**：删除该功能后，核心目标是否更难实现？若否，降为辅助功能或删除。
- **创新检查**：每个亮点必须说明“相比什么，具体改善了什么”。
- **实验检查**：实验指标必须能说明核心问题是否得到改善，或装置性能是否满足使用需要。

### 4. 确定动态页面

依据 [presentation-framework.md](references/presentation-framework.md) 选择章节和页面。保持“背景与现状—目标与方案—制作与原型—实验与分析—总结”的章节顺序，但允许：

- 没有有意义的访谈/问卷时省略调研页。
- 图纸或原理复杂时拆页。
- 制作、实验素材较多时按关键选择或实验主题增页。
- 没有真实制作、原型或实验素材时保留必要的“丢失/待补”占位，不伪造证据。

每页只承担一个主要结论。页面标题优先写结论，不只写“项目背景”“实验结果”等栏目名。

面向小学生时，正文通常保留3–4个要点；原始参数、引脚、完整阈值和代码细节移入逐页参考稿，只在实验或技术页保留最能说明问题的一组。目标页可以用“一句话目标 + 3–4个功能”，不要把整段项目书搬上页面。

### 5. 生成内容与演示

默认生成本地素材可离线打开的 HTML；用户选择后再同步生成 PPTX。优先使用模块内确定性脚本和模板，不临时自由编写另一套生成器。

按 [defense-spec.schema.json](references/defense-spec.schema.json) 形成答辩内容 JSON，并依次运行：

```bash
node modules/idealab-presentation/scripts/scan-defense-materials.mjs --archive "学生档案" --output "06 答辩ppt" --name "姓名-项目简称"
node modules/idealab-presentation/scripts/validate-defense-spec.mjs --input "答辩内容.json"
node modules/idealab-presentation/scripts/build-idealab-presentation.mjs --input "答辩内容.json" --inventory "姓名-项目简称-答辩素材盘点.json" --output "06 答辩ppt"
```

扫描结果只能提供候选，AI必须查看文档、图片画面并预览视频内容后再请用户确认。确认后先把每个检查项的 `needs-review` 改为 `present`、`missing` 或 `not-applicable`；实际使用的文件还要把 `review_status` 改为 `approved` 并核对 `origin`。选中的学生视频必须把 `video_role` 确认为 `student-demo`；老师参考视频保持 `teacher-reference`，不得选入。新生成的示意图加入盘点 `items`，标记 `origin: ai` 与 `review_status: approved`。最后再把盘点 JSON 的 `review.confirmed` 与答辩内容的 `plan_confirmed` 设为 `true`。生成器会核对两份文件来自同一个学生档案，并逐项确认所有引用图片和视频；不会联网，也不会自行制造证据素材。

内容要求：

- 封面使用契合项目主题的全幅背景图，标题和学生信息用HTML/PPT文字叠加；背景图内不要生成中文文字，不放 ideaLab logo。
- 正文使用简洁的“标题 + 精炼文字 + 图片/图表”结构，保证投屏可读。
- 现有方案必须围绕项目痛点比较；不足要自然引出本项目优势和创新。
- 现有方案图片按“本地已有截图 → 无需登录的百度图片/官网/公开产品页 → 生图模型生成适合讲解的画面”选择。淘宝要求登录时立即跳过，不让学生登录或提供账号。生成图片不需要在演示页面额外标注。
- 现有方案有三项时，必须提供“1张同时包含三种方案的完整对比图”，或“每项方案各1张图片”；不能只给第一项配图、其余两项留空。图片顺序与 `existing_solutions` 顺序一致。单张总览图优先生成3:4或4:5纵向构图，三个方案分区清楚，适配页面左侧大图位。
- 本地原型、过程和实验素材缺失时显示明确占位，写清要补的画面，不用AI假图替代。
- 学生演示视频使用 `videos` 字段，保留原视频并在HTML中显示播放器，点击即可播放；不要截成关键帧代替视频。每页最多一个视频，优先放在原型或功能演示页。
- 老师或教师演示视频只作项目理解参考，不进入最终答辩。若学生版缺失，显示待补占位。
- 现有方案的优缺点不强制逐条提供来源；应根据目标人群、使用场景和核心问题进行推导，并讲清“哪里不足，因此本项目为什么这样设计”。
- 已选择的素材必须全部实际显示；不能因版式容量不足而静默丢弃。
- 观众页面不显示内部工作语言，例如核心问题链、logic_link、素材状态、AI生成说明或制作提示。逻辑链用于组织内容，逐页参考稿用于解释，不占用幻灯片底部。
- 使用模板的章节版式：问题页突出场景与3个痛点；现有方案页使用一图总览或三图三栏；目标页使用“核心目标/关键功能”双栏；制作与原型页优先大图；实验页使用“方法/记录/结论”；总结页使用“核心成果/创新点/下一步”。

### 6. 整理实验

按 [experiments.md](references/experiments.md) 逐项采访学生已有实验；根据年级决定功能验证、效率对比和性能测试的深度。

有记录时，从确认的数据生成表格、图表和结论。没有记录时，生成可执行的实验计划和记录表；若学生能确认做过什么及观察结果，可整理为定性结论，但不得发明次数、成功率或精确数值。

### 7. 生成逐页参考稿与练习页

按 [speaker-script-and-defense.md](references/speaker-script-and-defense.md) 为每页生成自然、口语化的参考讲法和过渡句。讲稿服务于学生理解，不逐字朗读页面文字；个人经历、贡献和数据缺口保留醒目占位。

另生成独立交互练习页，按项目材料给出背景与目标、方法与实验、整体理解与个人贡献等问题。参考答案默认折叠，允许换题、标记“已经会了/还需练习”并显示进度。不要自动强迫学生进入实时模拟答辩。

### 8. 验收与保存

至少输出：

```text
{姓名}-{项目简称}-答辩素材盘点.md
{姓名}-{项目简称}-答辩演示.html
{姓名}-{项目简称}-答辩逐页参考稿.md
{姓名}-{项目简称}-答辩练习.html
{姓名}-{项目简称}-答辩演示-媒体/      # 选择学生演示视频时生成
{姓名}-{项目简称}-答辩PPTX.pptx   # 仅在用户选择时
```

保存到当前学生档案的 `06 答辩ppt` 下，保留本地素材副本和相对路径；同名时使用 `-v2`、`-v3`，不得覆盖旧版。

完成前逐项确认：

- 姓名和项目简称正确，且出现在演示封面和文件名中。
- 因果链完整，现有方案不足确实引出本项目亮点。
- 页面没有文字溢出、图片变形、重叠、断图或选中素材丢失。
- 逐页查看最终画面，确认没有大面积无意义留白；现有方案、目标、制作/原型、实验、总结分别使用与任务匹配的版式，而不是全篇重复同一种左右栏。
- 学生演示视频能在HTML中点击播放，媒体目录与HTML放在一起；页面没有误用老师演示版。
- 所有真实/生成/缺失内容均正确标记。
- 实验结论与学生确认的材料一致，深度符合年龄段。
- 逐页参考稿与演示页一一对应，练习页折叠和进度交互可用。
- HTML可离线打开并适合16:9投屏；PPTX如生成则页数一致且可打开。
