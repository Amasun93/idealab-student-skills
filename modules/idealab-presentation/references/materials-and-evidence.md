# 素材盘点与证据边界

生成演示前必须先完成素材盘点并获得确认。

## 目录

1. 扫描范围
2. 判定类别
3. 真实性等级
4. AI生成边界
5. 缺失占位
6. 确认格式

## 1. 扫描范围

读取当前学生档案内实际存在的：

- 开题书、项目手册、项目卡、研究日志。
- 概念图、工作流程图、硬件框图、结构图、CAD/建模文件。
- 代码、接线图、元器件清单、调试记录。
- 制作过程照片、原型照片和原始演示视频。
- 实验表格、手写记录、结果照片、问卷、访谈或观察材料。
- 已有PPT、HTML、论文或讲解稿。

查看内容后再分类：图片要看画面，视频要预览人物、装置和演示内容，文档要读正文。文件名只能作为线索。

视频必须额外标记：

- `student-demo`：学生本人操作、讲解或展示作品，可进入最终答辩。
- `teacher-reference`：老师或教师的演示、讲解，只用于帮助AI理解项目，不进入最终答辩。
- `needs-review`：仅凭文件名无法确认人物身份，先请老师或学生确认。

同一项目同时存在学生版和老师版时，只选择学生版。没有学生版时建立“待补拍学生演示视频”占位，不用老师版替代。

## 2. 判定类别

每项材料归入以下之一：

| 类别 | 判定 | 后续动作 |
|---|---|---|
| 完整可用 | 清晰、相关、含义明确、版本合适 | 写明将用于哪一章节 |
| 可用但需确认 | 人物/场景/日期/版本/实验含义不确定 | 一次确认一个关键事实 |
| 缺失待补 | 因果链需要，但本地没有真实材料 | 建占位并写具体补拍要求 |
| 允许AI生成 | 属于说明性视觉而非学生真实过程 | 列出提示方向和页面用途 |
| 不使用 | 重复、低清、无关、无法辨认或隐私风险 | 说明原因，不删除原文件 |

“没有调查材料”不等于必须建立缺失调研页。调研页是可选项；只有项目逻辑确实依赖某项调查结论时才列为待补。

## 3. 真实性等级

内容按证据强度处理：

1. **已核实事实**：本地材料可直接证明，或学生/老师明确确认。
2. **来源事实**：来自真实产品页、新闻、公开资料；保留名称、来源和访问时间。
3. **学生口述**：标明由学生确认，可用于个人经历、贡献和定性观察。
4. **设计计划/推断**：用“计划、预计、待验证”表达。
5. **AI示意**：只用于帮助理解，显著标注，不作为证据。

不要把项目卡、开题书中的计划自动升级为“已实现”。不要把AI总结出的合理性当作学生经历。

## 4. AI生成边界

### 可以生成

- 封面背景图。
- 问题由来中的生活场景插图。
- 现有方案的产品画面、使用场景、原理或对比图。
- 基于确认事实的概念图、流程图、硬件框图和原理示意。
- 缺失材料占位图标或版式背景。

### 不可生成来冒充真实证据

- 学生或老师制作过程照片。
- 原型成品、装置现场和演示截图。
- 实验过程、测试数据、用户使用和采访现场。

生成图片在内部素材盘点中保留 `origin: ai`，演示页面不需要额外标注。内部记录只用于避免把生成图片误当成学生真实制作、原型或实验材料。

现有方案分析在学生材料不足时，可以先检索代表性产品或方法；如果公开页面不方便查看或画面不适合讲解，可以直接生成更清楚的产品场景、原理或对比画面。

### 现有方案图片优先级

1. 先使用学生档案中已有且清楚的调研截图、产品图或来源截图。
2. 本地没有时，搜索无需登录即可打开的百度图片、品牌官网、公开产品页、新闻或科普页面，并保留页面名称、网址和访问时间。
3. 淘宝或其他电商页面一旦要求登录、验证码或账号授权，立即跳过；不要求学生登录，不索取账号，也不让登录阻塞答辩制作。
4. 公开图片模糊、版式混乱或不能清楚解释方案时，调用生图模型生成适合演示的产品场景、方案原理或对比画面。

现有方案的优点和不足不要求逐条附真实来源。根据项目设计方法论分析即可：这个方案面向谁、在什么场景下怎样解决问题、为什么仍不能充分解决本项目的核心问题、因此本项目增加了什么功能。重点是把推导理由讲明白。素材安排表中出现“淘宝调研截图待补”时，不把它设为阻塞项，应按以上顺序自动寻找公开替代或提出生图方案。

## 5. 缺失占位

对原型、制作或实验等不可生成的材料，演示中显示：

```text
丢失 / 待补
需要：能看清【主体】正在【动作/状态】的照片
建议补充人：【学生姓名/负责老师/待确认】
用途：【制作过程/原型成品/实验结果】
```

占位必须足够具体，使老师能直接安排补拍。例如“补一张照片”不够；应写“补拍装置正面全景，灯光点亮且书籍标签同时入镜”。

学生演示视频以原视频形式放入演示页，显示播放控件并可直接点击播放，不抽取关键帧代替。输出时复制到答辩演示的媒体目录，HTML和媒体目录必须一起保留。CAD、渲染图可说明结构计划，不能标成实物照片。

## 6. 确认格式

生成前向用户展示简明表格：

| 章节 | 将使用的本地材料 | 缺失/待确认 | 计划生成 |
|---|---|---|---|
| 问题由来 | … | … | 生活场景示意图 |
| 现有方案 | … | … | 原理示意图 |
| 解决方案 | … | … | 流程图（基于已确认功能） |
| 制作与原型 | … | 原型正面图待补 | 不生成实物图 |
| 学生演示视频 | 学生演示版.mp4 | 学生身份待确认/待补拍 | 不使用老师版代替 |
| 实验 | … | 成功次数待确认 | 只生成记录表/图表样式 |

然后明确询问：“以上素材安排是否确认？确认后我再生成演示、逐页参考稿和练习页。”

如计划生图，追加提醒切换到生图能力较好的模型。用户修改计划后更新盘点，再确认一次；不要保留已否决的材料。
