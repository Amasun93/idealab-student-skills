# 逐页参考稿与交互式答辩练习

逐页参考稿帮助学生理解和讲清项目；练习页帮助学生熟悉提问逻辑。两者都以真实项目材料为基础，不生产一篇模板化、只能照背的标准答案。

## 目录

1. 逐页参考稿
2. 讲解逻辑
3. 缺口标记
4. 交互练习页
5. 项目化提问
6. 参考答案

## 1. 逐页参考稿

每页按以下格式输出：

```markdown
## 第N页｜结论式标题

**这一页要讲明白：** 一句核心目的

**参考讲法：**
自然、口语化的1–3段。解释图片和逻辑，不逐字念页面。

**过渡：**
一句把当前结论带到下一页的话。

**需要学生补充：**
- [待确认：真实经历/个人贡献/实验数字]
```

稿件长短以“老师或学生照着能顺畅拍一遍、听众能理解”为准，不以字数为目标。开门见山，不使用“今天我们不讲……”等绕行句。

## 2. 讲解逻辑

### 问题与背景

从学生和目标人群能理解的生活常识讲起：场景里原本要做什么、哪里麻烦、为什么会影响人。公共背景可直接解释；个人经历未确认时提供故事结构和待补位置，不把它写成既成事实。

### 现有方案与创新

先说明现有方法怎样帮助人，再指出它在当前场景的具体限制。随后讲“因此我设计了什么功能”，让创新是推导结果，不是最后突然出现的口号。

### 功能与技术

先讲功能要产生什么效果，再讲输入—处理—输出和元器件。让学生理解为什么需要这些传感器/模块，避免把硬件清单当讲解。

### 制作与原型

突出关键选择、失败和修改。照片旁说明“我在做什么、为什么这样做”，不按时间流水账念图。

### 实验与结论

讲清“我想证明什么—怎么测—看到什么—所以认为怎样”。小学生用简单观察，初高中逐步加入对比、变量和数据。结论回到核心目标。

## 3. 缺口标记

使用醒目而具体的占位：

- `[请补充：你第一次注意到这个问题的真实场景]`
- `[请确认：这部分代码/结构是不是你亲自修改的]`
- `[待填写：共测试__次，成功__次]`
- `[待补拍：装置完成一次完整任务的正面视频]`

不要使用含糊的“此处补充内容”。练习参考答案中也保留相同占位。

## 4. 交互练习页

单独生成 `{姓名}-{项目简称}-答辩练习.html`，不要嵌入观众演示页。至少具备：

- 按类别筛选：背景与目标、方法与实验、整体理解与个人贡献。
- 随机或顺序显示一道项目专属问题。
- “查看参考答案”折叠区，默认关闭。
- “换一道题”“已经会了”“还需练习”。
- 已练习、已掌握、待复习数量和进度。
- 本地离线可用，不依赖登录或网络。

默认由学生自行点题练习，不自动开始计时或强制实时模拟答辩。

## 5. 项目化提问

隐藏模板页提供的是提问方法，不是固定题库。结合项目材料改写问题：

### 背景与目标

- 你为什么会关注【具体问题】？
- 【目标人群】在【场景】里最麻烦的一步是什么？
- 你的核心目标为什么选择【指标】，而不是增加更多功能？
- 这个项目对其他人有什么实际帮助？
- 你怎样判断自己大致实现了目标？

### 方法与实验

- 为什么选择【传感器/结构/交互】来实现【功能】？
- 概念图、工作流程图和硬件框图分别说明什么？
- 你的实验与什么方法比较？哪些条件保持一致？
- 【某次失败】为什么发生？你改了什么？
- 哪个实验最能说明核心问题得到改善？
- 如果测试次数增加，你预计最容易暴露什么问题？

### 整体理解与个人贡献

- 现有【代表性方案】已经能做什么，你的项目具体不同在哪里？
- 有没有更简单的办法？为什么仍选择当前方案？
- 你在项目中亲自完成或决定了什么？
- 你学会了什么，哪个判断发生过改变？
- 如果再做一版，你最先改哪里？
- 还有哪个重要问题没有被问到？

根据年龄调节措辞和深度：小学生问具体动作与现象；初中生追问比较和修改；高中生追问变量、误差、边界和取舍。

## 6. 参考答案

每个答案包含：

1. **先给结论**：一句直接回答。
2. **再讲依据**：来自哪张图、哪个功能、哪次实验或哪项材料。
3. **回到核心目标**：这说明项目怎样回应核心问题。

答案必须贴合当前项目，不能只替换项目名。没有真实信息时写清待确认项，例如：

```text
我选择这个方案，是因为它可以直接改善【核心指标】。
目前从【已确认材料】可以看到【事实】；
[待补充：学生本人为什么选择这一模块，以及是否尝试过其他方案]。
```

个人贡献只能来自学生确认。实验数字只能来自记录或学生明确回答。参考答案是“供理解和练习”，鼓励学生用自己的话表达。
