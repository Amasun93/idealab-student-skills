# 项目设计与答辩的因果链

本文件提炼自 ideaLab 老师备课逐字稿《项目设计原理》。用于理解项目，不用于把所有项目改写成相同文案。

## 目录

1. 不变框架
2. 背景与学生连接
3. 现状与代表性方案
4. 唯一核心目标
5. 功能、技术与图纸
6. 制作与真实性
7. 实验与目标闭环
8. 总结与创新

## 1. 不变框架

项目从开题、制作到答辩始终遵循：

```text
背景 → 现状 → 目标 → 方案 → 制作 → 实验 → 总结
```

答辩呈现时进一步展开为：

```text
目标人群遇到什么问题
→ 这个问题是否普遍、为什么值得解决
→ 现有产品或方法怎样解决
→ 现有方案为什么仍不能满足本项目场景
→ 本项目只聚焦哪一个核心目标
→ 哪些功能分别回应哪些不足
→ 这些功能需要什么原理、技术和元器件
→ 怎样做出原型
→ 用什么实验证明目标、效率或性能
→ 得到什么结论，还有什么可改进
```

逻辑优先于页数、外形和功能数量。评委提出意外问题时，也回到“核心问题—核心指标—功能是否服务指标—实验怎样验证”作答。

## 2. 背景与学生连接

背景要同时回答三件事：

1. 学生为什么会关注这个问题。
2. 目标人群在什么具体场景中遇到什么困难。
3. 这个问题为什么不只是个例，具有怎样的社会价值。

可将公共事实和合理的故事讲法写成学生容易理解的生活场景，但不要把未确认的亲身经历写成事实。个人经历不清楚时使用 `[请补充：你第一次注意到这个问题的真实场景]`。

视觉素材应让听众一眼看到问题：生活场景、使用障碍、对比状态或能说明严重程度的数据。只讲“市场广阔”“大家都需要”不能证明问题成立。

## 3. 现状与代表性方案

现状不是泛泛搜索，而是回答：

- 有没有人尝试解决。
- 有哪些具有代表性的产品、技术或人工方法。
- 它们在本项目场景下做得好和做得不够的地方是什么。

学生材料未提到现有方案时，搜索淘宝、电商、新闻、官方产品页或同主题解决方法。找不到完全相同的产品时，扩大到同一核心问题的相邻方案。例如研究“盲人坐公交”时，可比较盲道、导航、导盲犬和公交辅助服务，而不是宣称“从来没人做过”。

比较维度必须由项目痛点和目标产生，例如完成时间、识别准确度、需要多少人工协助、交互是否直观、适用人群、场景限制、成本和体积。不要只写“价格高、功能少”。

现有方案的不足要直接导出本项目的优势：

```text
现有方案在关键场景中缺少/受限于 X
→ 因此本项目设计功能 Y
→ Y 预计改善指标 Z
→ 后续通过实验 E 验证
```

## 4. 唯一核心目标

一个项目优先解决一个核心问题。把目标写成一句话：

```text
为【目标人群】在【具体场景】中改善【一个核心问题/指标】。
```

工程项目常体现为效率或效果提升，如更快、更准确、更稳定、更省力、更容易理解或更容易参与。人文传播项目也需要可判断的效果，例如让受众更快理解文化寓意、愿意互动或能正确完成某个动作。

出现多个目标时，追问：“哪个问题最重要？其他功能是否帮助这个指标？”无直接帮助的功能降为辅助、未来拓展或删除。

## 5. 功能、技术与图纸

从目标推导功能，而不是从元器件拼功能：

```text
问题/不足 → 所需效果 → 功能 → 输入 → 处理 → 输出 → 元器件/技术
```

例：需要“让归位位置更直观”时，功能可以是识别书籍后点亮对应仓位；技术再落到NFC识别、控制器匹配和灯光输出。

三类图承担不同任务：

- **概念图**：展示理想状态、使用场景、主要结构和效果。即使不看标题，也应大致看懂装置做什么。
- **工作流程图**：展示用户和装置按时间发生什么，突出输入—判断—输出。
- **硬件框图**：展示传感器、控制器、通信、电源和执行器之间的关系。

必要时增加技术原理或先验实验。先验实验用于确认关键原理或理论计算是否可靠，不是每个低龄项目都强制要求。

## 6. 制作与真实性

制作过程要证明学生参与和项目真实发生过。优先选择能体现关键决策的材料：图纸调整、建模切片、编程、电路连接、加工、组装、上色、调试、失败和修改。

不要做无解释的照片墙。每组过程图回答：当时在做什么、遇到什么问题、为什么这样改。原型页要展示整体和关键部件，必要时用视频真实关键帧补充，但标清来源。

## 7. 实验与目标闭环

“灯能亮、声音能响”只证明基础功能触发。项目的主要实验应证明：

1. **效率或效果是否改善**：与原有方法/现有方案对比，尽量控制其他变量。
2. **性能是否满足使用需要**：准确率、响应时间、识别距离、稳定性、续航、承重、耐久或适用范围等。

目标和实验必须互相对应。目标是“减少找书时间”，实验就比较相同任务、相似条件下不同方法的耗时；目标是“帮助理解非遗动作”，实验可比较使用前后正确识别或复述的表现。

低成本替代实验也有价值：把真实问题模型化，用身边材料做可重复的简化测试。精度有限时说明测试条件，不需要为了形式追求昂贵设备。

## 8. 总结与创新

总结回答：核心目标实现到什么程度、证据是什么、还可以怎样改。

创新点不是口号，而是因果链的结果：

```text
相较【代表性方案】
本项目用【具体功能/结构/交互/实验方法】
改善【核心不足或指标】
```

创新可以来自应用场景、交互方式、技术组合、结构设计或替代性实验方法。每项创新最好能回指一个作品事实或实验结论。

## 9. 快速自检

让学生能用自己的话回答四个问题：

1. 我做了什么？
2. 我为什么做？
3. 我怎样设计和做出来？
4. 我怎样知道它大致有用？

再检查：

- 问题是否具体到人、场景和困难。
- 现有方案不足是否与本项目亮点一一对应。
- 功能是否全部服务同一个核心目标。
- 技术是否解释了功能如何发生，而不是罗列元器件。
- 实验是否验证目标或关键性能。
- 结论是否能沿原链路返回核心问题。
