# 答辩演示的动态结构

本框架以工程类PPT模板前16页作为正文版式合同，以隐藏的第17–23页作为讲稿和问答方法。页面数量可以按素材增减，但每一页必须使用最接近的模板原型，不允许模型自由发明正文布局。

## 目录

1. 章节顺序
2. 动态页面表
3. 图文结构
4. 封面与视觉规则
5. 页面取舍

## 1. 章节顺序

保持以下章节逻辑：

1. **背景与现状**：为什么做，问题是否值得解决，现有办法还缺什么。
2. **目标与方案**：只解决什么核心问题，功能怎样对应，技术怎样实现。
3. **制作与原型**：学生怎样做，作品实际到了什么状态。
4. **实验与分析**：怎样检验，得到什么结果或还缺什么记录。
5. **总结**：结论、创新、限制和下一步。

五分钟以内通常不需要独立目录页和纯“谢谢”页。时间较长或章节较多时再加入目录。

## 2. 动态页面表

| 页面任务 | 状态 | 核心内容 | 推荐视觉 |
|---|---|---|---|
| 封面 | 必选 | 学生姓名、项目全名/简称、一句话定位 | 全幅主题背景或高质量原型图 |
| 问题由来 | 必选 | 学生视角、目标人群、具体场景、2–3个痛点 | 固定2张直观场景图 |
| 调研/访谈 | 可选 | 有代表性的真实发现，不做形式性问卷 | 4–6项材料中择重点，必要时拆页 |
| 现有方案 | 必选 | 3个代表性产品/方法、优点、核心不足 | 固定3张独立图片，与三个方案一一对应 |
| 核心目标与功能 | 必选 | 一个目标；痛点—功能对应关系 | 对照表、功能关系图 |
| 灵感/技术原理 | 条件页 | 方案来源、关键现象、技术原理或先验实验 | 原理示意、生活应用、先验结果 |
| 解决方案 | 必选 | 概念图、工作流程、硬件框图 | 左侧大概念图，右侧上下为硬件框图和流程图 |
| 制作过程 | 成果答辩必选 | 关键步骤、困难、选择和修改 | 真实制作照片、代码/建模截图 |
| 原型成品 | 成果答辩必选 | 整体、关键部件、一次完整任务 | 1–2张真实照片，可加1个学生演示视频播放器 |
| 实验设计 | 必选 | 测什么、怎样测、怎样判断 | 实验流程、变量、记录表 |
| 单项实验 | 动态1–N页 | 目的、方法、过程、数据、结论 | 真实过程图、表格或图表 |
| 总结 | 必选 | 核心结论、创新、限制/下一步 | 代表性作品或过程图 |

调研页只有在存在有意义的问卷、访谈、观察或可靠数据时加入；没有就省略，不把“缺少调研”当作整份演示失败。

开题或阶段展示尚无实物时，将制作、原型和实验结果改成“制作计划、验证计划、待补材料”，不要伪装成已完成成果。

## 3. 图文结构

每页先确定一句“听众听完应该知道什么”，再选版式：

- **单图重点页**：一张大图 + 1个结论 + 2–3条标注。用于概念图、原型、流程。
- **双图对比页**：两个方案/状态 + 相同维度 + 一句结论。用于问题场景、现有方案和实验前后。
- **对应关系页**：上方只放一句核心目标；下方左列“解决”、右列“关键功能”，每行一一对应，保留2–4组。用于目标与功能。
- **过程页**：3–5个按顺序的关键步骤，每步一句“动作 + 决策/发现”。
- **实验页**：左侧方法/变量，右侧图表/结论；结果数字必须能追溯。

不要让所有页面都复用同一个“左文右图”版式。按原工程类模板的沟通任务使用以下稳定结构：

- **问题由来 / `problem-two-scenes`**：固定2张场景图，下面保留2–3个痛点和一句项目问题。场景图允许基于当前项目事实生成。
- **调研访谈 / `research-grid`**：仅在真实材料存在时加入，使用4–6张问卷、访谈、观察或数据材料；不足4项时删除该页，不用其他项目材料补齐。
- **现有方案 / `current-state-three`**：固定3图3栏。每栏依次放独立图片、名称、解决办法、优点和不足；页面底部用一句话引出本项目。禁止一张总览图代替三个图片位置。
- **核心目标与功能**：严格沿用工程模板第6页的阅读顺序。页头为“背景综述：核心目标与功能”；下一行突出一句核心目标；下方使用两个等宽色块，左列列出2–4个具体问题，右列放对应功能。第1个问题必须对应第1个功能，不能把左列写成长段项目介绍，也不能只写功能清单。

目标页在JSON中使用 `goal_statement` 和 `goal_pairs`，不要用普通 `bullets` 代替：

```json
{
  "section": "goal",
  "title": "项目自己的目标页标题",
  "goal_statement": "帮助谁，在什么场景下解决什么核心问题",
  "goal_pairs": [
    { "problem": "学生不知道动作是否做对", "function": "识别动作并立即反馈" },
    { "problem": "文化讲解依赖老师反复说明", "function": "按键播放对应文化故事" }
  ]
}
```

问题和功能都写成学生能读懂的短句。技术型号、参数和工作原理放到后面的方案页，不要塞进目标页。
- **技术原理 / `principle-two-visuals`**：左侧用短句解释原理，右侧固定2个原理或生活应用图位。
- **解决方案 / `solution-three-diagrams`**：严格对应模板第9页，左侧大图为概念图，右上为硬件框图，右下为工作流程图。三图都要出现；缺少时基于当前项目已确认内容生成，不借用其他项目图纸。
- **制作过程 / `making-grid`**：有材料时使用3–7张真实过程照片组成矩阵；完全缺失时只显示一个横向待补区。
- **原型成品 / `prototype-hero`**：1–2张真实原型图或1个学生演示视频作为页面主体；老师演示版不能进入。
- **实验设计 / `experiment-overview`**：用短句列出将验证的功能、有效性或性能维度，不放虚构结果。
- **单项实验 / `experiment-detail`**：上方固定实验目的和方法；下方左侧为过程素材、右侧为数据或记录；底部单独放结论。两个图位都保留，没有记录时分别写明待补。
- **总结 / `summary-evidence`**：左侧固定1个项目素材图位，右侧上方为创新点、下方为重难点或未来展望。

不要使用大段文章。正文以关键词、短句和标注为主，完整表达放在逐页参考稿。页面标题尽量结论化，例如“灯光定位减少了反复查找”优于“实验结果”。

所有选中的图片都必须实际显示。素材超过当前版式容量时，拆页或重新筛选，并在素材盘点中说明；不可静默忽略。

内部的 `logic_link` 和核心问题链只用于生成器检查，不显示在观众页面。幻灯片底部只保留必要页码，不重复整段核心问题。

视频不做成截图墙。每页最多放一个经确认的学生演示视频，保留原文件并显示播放控件；老师演示版不进入学生答辩。视频较长时在逐页参考稿中写明建议播放的时间段，但页面仍加载完整原视频。

## 4. 封面与视觉规则

- 16:9，适合教室投屏。
- 不放 ideaLab logo。
- 背景全幅、主题明确、有视觉焦点，并保留标题安全区。
- 背景图不含AI生成的中文；姓名和项目标题用HTML/PPT文本覆盖。
- 能力较弱的生成模型使用三种稳定布局之一：左文右景、居中文字上景下、底部标题上方主体。
- 模型只可以在封面安全区内调整标题位置；正文不因模型能力不同而改变模板结构。
- 正文简洁、内容优先，避免复杂背景和装饰；不靠缩小字号塞内容。
- 真实照片不拉伸、不裁掉关键主体；图表保留单位、样本量和必要标签。

封面优先使用生成的主题背景；如果真实原型照片非常清楚，也可使用真实原型并标注“实物原型”。

## 5. 页面取舍

决定增删页时依次判断：

1. 这页是否补上因果链中的一个必要环节。
2. 是否有足够材料支撑一个明确结论。
3. 是否与其他页重复。
4. 学生是否能用自己的话解释。

页面数量随项目变化。通常10–15页易于讲清，但不是硬限制。素材少时宁可短而完整；素材多时只保留能证明关键判断的内容。
