# 素材盘点与证据边界

生成演示前必须先完成素材盘点并获得确认。

## 目录

1. 扫描范围
2. 判定类别
3. 真实性等级
4. AI生成边界
5. 缺失占位
6. 确认格式

## 1. 扫描范围

读取当前学生档案内实际存在的：

- 开题书、项目手册、项目卡、研究日志。
- 概念图、工作流程图、硬件框图、结构图、CAD/建模文件。
- 代码、接线图、元器件清单、调试记录。
- 制作过程照片、原型照片、演示视频和视频关键帧。
- 实验表格、手写记录、结果照片、问卷、访谈或观察材料。
- 已有PPT、HTML、论文或讲解稿。

查看内容后再分类：图片要看画面，视频至少看代表性关键帧，文档要读正文。文件名只能作为线索。

## 2. 判定类别

每项材料归入以下之一：

| 类别 | 判定 | 后续动作 |
|---|---|---|
| 完整可用 | 清晰、相关、含义明确、版本合适 | 写明将用于哪一章节 |
| 可用但需确认 | 人物/场景/日期/版本/实验含义不确定 | 一次确认一个关键事实 |
| 缺失待补 | 因果链需要，但本地没有真实材料 | 建占位并写具体补拍要求 |
| 允许AI生成 | 属于说明性视觉而非事实证据 | 列出提示方向和标签 |
| 不使用 | 重复、低清、无关、无法辨认或隐私风险 | 说明原因，不删除原文件 |

“没有调查材料”不等于必须建立缺失调研页。调研页是可选项；只有项目逻辑确实依赖某项调查结论时才列为待补。

## 3. 真实性等级

内容按证据强度处理：

1. **已核实事实**：本地材料可直接证明，或学生/老师明确确认。
2. **来源事实**：来自真实产品页、新闻、公开资料；保留名称、来源和访问时间。
3. **学生口述**：标明由学生确认，可用于个人经历、贡献和定性观察。
4. **设计计划/推断**：用“计划、预计、待验证”表达。
5. **AI示意**：只用于帮助理解，显著标注，不作为证据。

不要把项目卡、开题书中的计划自动升级为“已实现”。不要把AI总结出的合理性当作学生经历。

## 4. AI生成边界

### 可以生成

- 封面背景图。
- 问题由来中的生活场景插图。
- 现有方案的解释性插图；真实产品事实仍需真实来源。
- 基于确认事实的概念图、流程图、硬件框图和原理示意。
- 缺失材料占位图标或版式背景。

### 不可生成来冒充真实证据

- 学生或老师制作过程照片。
- 原型成品、装置现场和演示截图。
- 实验过程、测试数据、用户使用和采访现场。
- 虚构淘宝商品截图、虚构品牌或伪造来源。

生成视觉统一标注“AI生成示意图”“概念示意”或“非实物图”。

现有方案分析在学生材料不足时，应先检索真实代表性产品或方法。若需要更清晰的讲解画面，可基于已核实事实生成“方案原理示意”，但不能把生成图称为某个真实商品照片。

## 5. 缺失占位

对原型、制作或实验等不可生成的材料，演示中显示：

```text
丢失 / 待补
需要：能看清【主体】正在【动作/状态】的照片
建议补充人：【学生姓名/负责老师/待确认】
用途：【制作过程/原型成品/实验结果】
```

占位必须足够具体，使老师能直接安排补拍。例如“补一张照片”不够；应写“补拍装置正面全景，灯光点亮且书籍标签同时入镜”。

真实视频可以截取关键帧补充原型或过程，但要标注“视频截图”和视频文件名。CAD、渲染图可说明结构计划，不能标成实物照片。

## 6. 确认格式

生成前向用户展示简明表格：

| 章节 | 将使用的本地材料 | 缺失/待确认 | 计划生成 |
|---|---|---|---|
| 问题由来 | … | … | 生活场景示意图 |
| 现有方案 | … | … | 原理示意图 |
| 解决方案 | … | … | 流程图（基于已确认功能） |
| 制作与原型 | … | 原型正面图待补 | 不生成实物图 |
| 实验 | … | 成功次数待确认 | 只生成记录表/图表样式 |

然后明确询问：“以上素材安排是否确认？确认后我再生成演示、逐页参考稿和练习页。”

如计划生图，追加提醒切换到生图能力较好的模型。用户修改计划后更新盘点，再确认一次；不要保留已否决的材料。
