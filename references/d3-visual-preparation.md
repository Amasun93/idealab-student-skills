# D3 三张图准备器

在生成开题答辩HTML之前，先读取当前学生的开题书、项目卡、开题书参考图和本轮对话，准备概念图、工作流程图和硬件框图。三张图未完成前不要编译HTML。

## 目录

- 共用事实卡
- 概念图
- 工作流程图
- 硬件框图
- 保存与交接

## 共用事实卡

先整理一份仅供本轮使用的事实卡：

- 项目名称与使用者。
- 作品准备解决的问题。
- 作品大致外形与使用场景。
- 用户动作、传感输入、控制判断和输出反馈。
- 已确认的传感器、执行器、电源、通信和主控。
- 项目是否实际使用AI；若使用，AI的输入、能力、输出和运行位置。
- 开题书没有写清、学生也没有说明的内容。

只使用开题书、项目卡和学生本轮明确说过的内容。未知内容写入待确认，不得为让图更专业而补造模块、数据、型号或功能。主控没有另行确认时默认使用ESP32。

## 概念图

### 生成顺序

1. 先问一次：“你有自己画的作品草图吗？”草图用于理解学生设想和最终兜底，不作为默认首选成图。
2. 根据开题书描述、开题书参考图和学生补充内容生成一张AI概念图。
3. 查看生成结果并逐项执行质量检查。
4. 第一次不合格时，只针对失败项修改提示词并重新生成一次。
5. 第二次仍不合格时，使用学生手绘图；没有手绘图时使用开题书参考图并做清楚标注。不要继续反复生图。

### 生成要求

- 输出清晰的16:9横向PNG或JPG，建议不低于1280×720。
- 让实体作品成为画面主体，完整展示作品大致外形、结构、材质和关键部件位置。
- 展示人物或手部怎样使用作品，并交代真实使用场景。
- 用灯光、声音、动作、屏幕或其他可见方式表现至少一种核心交互效果。
- 保留开题书参考图和学生设想中的核心结构，不擅自更换产品形态。
- 允许3—5个简短中文标注；优先后期叠加标注，避免生图模型生成乱码。
- 不使用流程框、硬件框、思维导图或大段说明文字充当概念图。

### 硬性不合格条件

出现任意一项即不合格：

- 只有方框、箭头和文字，没有可辨认的实体作品。
- 看不出作品长什么样，或作品不是画面主体。
- 看不出谁在什么场景中怎样使用。
- 没有表现任何核心交互效果。
- 与开题书参考图明显冲突，或新增未确认的主要功能和零部件。
- 中文乱码、主体模糊、严重裁切或清晰度不足。
- 画面实际是流程图、硬件框图、思维导图或普通信息图。

通过时用一句话记录：作品主体是什么、谁怎样使用、画面展示了什么交互。同时填写概念图质量检查：实体作品、人物或手部、使用场景、交互效果、符合开题书、画面清晰。AI生成图六项必须全部通过；若一句话无法根据画面本身说清，视为未通过。

## 工作流程图

流程图用于把项目真正的运行逻辑讲明白。儿童化只体现在用词、分组和阅读顺序上，不得通过删除关键步骤来实现。

1. 先让学生用自己的话讲一次“作品从开始到产生结果是怎样工作的”。
2. 用开题书和项目卡补齐学生漏说但已经确认的逻辑；不得新增功能。
3. 按实际项目保留用户动作、传感输入、主控判断、执行输出、用户反馈、循环和必要的异常处理。
4. 项目有多种模式时分成清楚的模式或泳道，例如手持模式、讲解模式、自动展示模式。
5. 允许多个必要判断分支，不固定节点数量；通常以6—12个主要节点为宜，复杂项目可以增加，但要分组。
6. 节点标题使用学生能复述的短句；算法、协议和专业参数放到硬件图或讲稿，不堆进流程节点。
7. 箭头必须有稳定的阅读方向，分支和回路要有文字说明。

完成后请学生沿箭头讲一遍。学生无法说明某个节点为何存在时，先修改图或补充理解，再进入下一张图。

## 硬件框图

硬件框图使用儿童友好的思维导图或分组框图，中心为项目名称，至少检查以下分支：

1. **传感器**：名称，以及它感知什么。
2. **执行器**：名称，以及它产生什么动作、灯光或声音。
3. **电源系统**：怎样供电；未确认的电压不要编造。
4. **通信系统**：模块之间怎样传递信息；未确认时写“待确认”，不要猜协议。
5. **控制模块**：默认ESP32，以及它读取、判断和控制什么；开题书明确使用其他主控时按原材料修改。
6. **AI能力**：仅在项目实际使用AI时显示，写清AI的输入、具体能力、输出和运行位置。

AI分支不得只写“使用AI技术”。示例：

```text
AI能力
└─ 识图模型
   ├─ 输入：摄像头拍摄的数字棋子图像
   ├─ 作用：识别数字和摆放位置
   ├─ 输出：识别结果
   └─ 运行位置：电脑端
```

每个模块都写“名称＋作用”，只使用已确认模块。硬件框图不替代工作流程图：它回答“有哪些模块、各自做什么”，流程图回答“事情按什么顺序发生”。

## 保存与交接

将三张图保存在当前学生档案的 `03 项目图纸/D3开题图纸/`，保留生成源文件；需要放入答辩HTML时由构建脚本复制副本。推荐文件名：

```text
01-概念图.png
02-工作流程图.svg
03-硬件框图.svg
D3图纸内容.json
```

三张图完成并由学生确认含义后，再读取 `references/classroom-deck-guide.md` 编译六页开题答辩HTML。

编译前先运行：

```bash
node scripts/validate-d3-visuals.mjs --input "D3图纸内容.json"
```

校验没有通过时，根据错误修正对应图片或内容，不绕过校验直接编译HTML。
